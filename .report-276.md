## 1. The defect, and the mechanism decision

Measured shape (both live runs): newest recorded verdict is the `fail` at the
head the handoff names, the fix round is recorded for that head, the classifier
returns `waiting-workers` / `supervision.fix_round_dispatched` with
`eligible: false` **before** step 7's progress-timeout branch is reachable — so
the run is reported as live work forever, and the bounded retry the run already
holds is never spent.

The deciding fact is not the clock, it is the leg's own state: the repair leg's
**recorded lane checkout no longer exists** on the host (`issues-261-impl2` and
the `#258` sibling; measured 2026-09-25 ~00:40 +07 — reproduced read-only: the
fleet's worktrees root now holds only the current `impl-*` worktrees). A leg
whose checkout is gone carries no state, so nothing can ever be delivered from
it and a wait on it has no end. Code paths followed:

- `src/supervision.rs:1735`-region `classify` fix-wait arm — returns before the
  frontier is ever derived.
- `dispatch_intent` (`src/supervision.rs:1023`-region) — derives `None` for this
  shape (the diagnosed-`refusal.delivery.unbound` attempt + `newest_verdict ==
  "fail"` fence), so the driver drives nothing (`SupervisorCore::reconcile`,
  `check_plan`): the park is structural, not a report.
- `#272`'s `fix_delivery_uncertified`/`fix_recollect_intent` requires
  `leg.delivered == true` from `observe_fix_leg_checkout`, which returns `None`
  when the checkout cannot be read — unreachable for these legs, and pointing
  the re-collect at `issues-261-impl2` would refuse (gone).
- `#202` AC2 (`check_certified_consumption`, `src/daemon.rs:2026`) — the fence
  the operator's own re-dispatch hit (`refusal.delivery.unbound`, operator key
  `ik_orch-p6-261-finish2`): the run consumes only a head its own collection
  certified, so the delivered head could not be consumed from outside either.

**Mechanism (chosen, and why it is the smallest one that satisfies the
outcome):** observe the leg's lane, not just its head; end the wait on that
observed fact; and let the run's own machinery re-enter its own review effect,
which re-creates the repair lane and hands the FAIL to a leg that can work. New,
deliberately **not** touched: `#272`'s fence, `#202` AC2, the tail's
verified-delivery gate. No operator control is needed for the advance, and no
head is consumed that the run's own collection did not observe — after the
re-dispatched round delivers, the *existing* `#272` re-collect certifies it.

Concretely, on the two live instances the chain is: classifier reports
`needs-attention` / `supervision.fix_round_lane_lost`, `eligible: true` → the
driver derives the ONE continuation (the handoff's own step) → the engine spends
the held retry (`consumed_at` + `consumed_key`, journaled apply) → the review
effect re-runs at the certified head → the recorded round's lane is gone, so it
is **superseded**: the engine creates the next round's lane at the certified
head and delivers the instruction to it → a live leg holds the FAIL → its
delivery is re-collected by the run's own collector (`#272`) → the review
consumes the certified head → the tail (`p7` merge, `p8` cleanup) is reached by
the run's own machinery. `p6-261`/`p6-258` therefore leave the park without any
`run.dispatch`, `run.retry` mint, `run.release`, `run.resolve` or
`run retire-lane`, and with no operator `mutate.*` apply key.

3. **AC6's `commands.rs` / `src/tui/supervision.rs` wording** — interpreted as
   the closed class vocabularies (see §3). Disclosed rather than papered over.
4. **Two consequences of the chain I should name plainly:**
   (a) the re-dispatched review re-runs at the *certified* head, so the reviewer
   leg is prompted again and the stale `pass` artifact at
   `<review_root>/<session>-p6-261.json` (written for the never-collected moved

## 7. Verdict on the live runs

I believe the two live runs will advance **by themselves** once the daemon runs
the merged binary, without any operator control, because every link the advance
needs is a recorded fact plus the run's own machinery (proved on the fixtures
above), and neither `#272`'s fence nor `#202` AC2 is loosened. Where I have
doubt: (i) it depends on a live repair leg actually picking up the re-delivered
instruction and committing (that is the run's own lane work, outside this lane's
proof); (ii) the re-dispatched review consumes a *fresh* reviewer verdict at the
certified head, so a live reviewer leg must run once more before the chain
closes — the stale `pass` for the moved head stays unreadable by design.
