## The defect, reproduced inside the repo

`refusal.delivery.unbound` (#202 AC2, `src/mutation.rs:369-372`) fires whenever a step
consumes a head the run's own collector never certified. A run whose own fix round
delivered a MOVED head has exactly that shape: the FAIL handoff was dispatched for the
pre-fix head, the repair leg's lane checkout moved past it, and there is no path by which
the run's own collector observes the new head — the collector is one-shot
(`refusal.run.step_done`), a re-evaluation addresses a terminal-success producer
(`refusal.run.reevaluation_step`), and the held bounded-retry authorization is refused by
`run release` (`refusal.run.retry_pending`). The run parks forever holding a counted slot.

Reproduced with a mutation probe against the committed witnesses (the probe neutralizes the
new re-collect derivation: `return None` as the first statement of the re-collect intent).
With the probe in place the live-daemon witness parks in precisely the reported shape — the
review re-entry is dispatched at the STALE certificate and refused, and nothing further
happens for the whole window:

    mutation-witness.log (RAW_EXIT=101):
    the run never re-bound its fix delivery: no progress for 120s of 121s waited;
    observed: ["t1 status=new next=m1/merge attempts=[(p1,succeeded),(s1,succeeded),(o1,succeeded),(r1,succeeded)]",
               "t2 status=new next=r1/review_evidence attempts=[...,(r1,refused)]", ... "t219 ..."]

The same probe fails the unit witness (`src/supervision.rs:4709`). Restored by copy +
sha256 check (`src/supervision.rs: OK`), both witnesses green again.

## What the run's own machinery now does (no operator step-dispatch)

1. `src/supervision.rs` — the supervision evidence carries the run's recorded DELIVERY
   BINDING (`state.rs`: read from the same rows the verified-delivery consumer reads), and
   two derived facts: the fix delivery is UNCERTIFIED (the newest recorded verdict is still
   the `fail` that names the pre-fix head) / RE-CERTIFIED. `fix_recollect_intent` derives
   the run's ONE bounded continuation from those facts plus the repair leg's observable
   checkout (`observe_fix_leg`, which until now informed classification only): the run's
   own committed collector step, reason `supervision.recollect.fix_delivery`. A handoff
   whose checkout cannot be read back, a leg that did not move, or an already-re-certified
   delivery derives nothing. `dispatch_intent` wires this BEFORE the frontier walk, and the
   review re-entry goes through the run's own bounded control
   (`supervision.reevaluation.next_round` = `run.reevaluate`, one recovery act, #243).
2. `src/daemon.rs` — `recollect_step_params` presents the committed collector step's own
   inputs with the repair leg's recorded lane checkout as the worktree the collection
   OBSERVES. The fix lane is the engine's own `git worktree add --detach` checkout
   (`src/lane.rs`), so the committed `branch` binding is dropped rather than fabricated; the
   observed branch is whatever that checkout holds, and a checkout left without a branch
   refuses typed. `method_apply_from`'s supervised-apply eligibility read now takes the
   SAME `observe_fix_leg` read the driver derived from, so a dispatch the driver derived is
   never refused for a fact the driver read.
3. `src/state.rs` — `SupervisionEvidence.delivery` (the run's recorded certified binding).

The #202 AC2 fence is untouched: the re-collect is a REAL collection (`collect_outcome`)
that observes the leg's checkout itself; the certificate only moves because a collection
observed the head.
