## 1. The defect (measured, at the base and in the wild)

`tests/supervision_reparse.rs::a_settled_worker_moves_the_frontier_on_the_next_tick`
failed intermittently on its own observation, never on the product: the driver
re-dispatches the step that IS still the frontier on every tick, and both
assertions read *however many intents had arrived* rather than *which frontier
the evidence moved the driver to*. The issue's captures show the two
signatures; this lane's base battery reproduced one of them three times (§3).

- **`:594`** — `assert_eq!(dispatcher.steps(), vec!["p1".to_string()], "the boot check dispatches the frontier")`
  — a bare snapshot with no wait. A tick landing between the check's commit and
  the read legitimately re-dispatches the still-current frontier, so the
  snapshot holds `["p1","p1"]`. (The check also commits BEFORE its dispatch is
  recorded, so the same bare read could as legitimately hold `[]`.)
- **`:625`** — `let steps = wait_for_steps(&dispatcher, 2, TICK_DEADLINE);` then
  exact equality against `["p1","p2"]`. The helper returned **"at least
  `count`"** (`if steps.len() >= count || started.elapsed() >= deadline { return steps; }`),
  so a third intent inside one 50 ms sampling window (`["p1","p2","p2"]`)
  failed it.

Both sites were quoted failing in the wild (`/tmp/flake-224/evidence/head-FAIL-11.log`,
`/tmp/flake-224/base-FAIL-44.log`, `/tmp/merged-verify/flake-FAIL-13.log` — the
issue's captures; those logs are older than this lane and were not re-run here).

## 2. What changed — `tests/supervision_reparse.rs` only (no `src/` change)

`git diff --stat dea843a1796f32c7a39940cd12308f534c990be6..HEAD` (against the
**branch point**; `origin/staging` has since advanced past it — it is now
`2e857bd`, from PR #297 and #216 — and this lane's evidence binds to
`dea843a`): `tests/supervision_reparse.rs | 51 +++++----` (41 insertions,
10 deletions) and this report file, nothing else
(`git diff --name-only dea843a1796f32c7a39940cd12308f534c990be6..HEAD`).

- **`RecordingDispatch::frontiers()`** (new): the recorded intents collapsed to
  successive distinct steps. A re-dispatch of the step that is STILL the
  frontier adds no entry; only a step the evidence MOVED the frontier to does.
  (`steps()` is untouched — the sibling test still reads raw intents.)
- **`wait_for_frontiers(dispatcher, count, deadline)`** (replaces
  `wait_for_steps`): waits until `count` frontiers exist, or the deadline
  passes, then returns exactly that **fixed, counted prefix** (`truncate(count)`)
  — never "however many happened to arrive". A short prefix fails the caller's
  assertion with the frontier that never arrived.
- **`:594`** now asserts `wait_for_frontiers(&dispatcher, 1, TICK_DEADLINE) == ["p1"]`
  — the FIRST frontier the driver acted on.
- **`:625`** now asserts `wait_for_frontiers(&dispatcher, 2, TICK_DEADLINE) == ["p1","p2"]`
  — the first two frontiers, still exactly the #268 intent: the settled step is
  not re-dispatched and the next step is.

Not weakened, and deliberately so: the collapse is over **consecutive**
duplicates only, so a frontier that went `p1 → p2 → p1` would still be visible;
and the assertion is on the frontier sequence, not on substrings/supersets. §4
proves the regression intent still bites.

```bash

# usage: battery-295.sh <label> <runs> <binary> <logdir>

  out="$logdir/$label-run-$i.log"

    cp "$out" "$logdir/$label-FAIL-$i.log"
    echo "run $i FAIL rc=$rc log=$logdir/$label-FAIL-$i.log"
  fi
done
echo "# battery=$label runs=$runs failures=$fails ended=$(date -u +%FT%TZ) load=$(uptime | sed 's/.*load averages: //')"
[ "$fails" -eq 0 ]
```

## 7. Residual risk (not fixed here)

1. **The sibling witness in the same file still reads raw counts.**
   `the_next_tick_classifies_the_evidence_recorded_since_the_last_one` asserts
   `dispatcher.steps() == ["p1"]` at its `:490` and `:524`. The same class of
   observation applies (an intent recorded by a tick that began before the
   run's own `record_attempt` can arrive after it), but it was never measured as
   flaky, and making it deterministic needs the recorded intent to carry the
   check that produced it — a product-surface change, outside this witness
   defect and outside the issue's scope.
2. **Out of scope by the issue itself** (recorded on the issue thread, not
   touched): the `mutation_engine` effect-deadline witness and the
   `review_dispatch` T1 30 s receipt poll.
3. **Load was natural, not injected.** The batteries ran back to back in one
   window under the fleet's own load (base 13.8→20.3, fixed 18.0→5.5); no
   bounded-contention burners were used, so the comparison is honest about the
   window rather than load-normalised.
4. **The fixed reads are bounded, not unbounded.** `wait_for_frontiers` fails at
   its deadline (30 s) if the driver never advances inside it — a host stalled
   that long still reds the witness, deliberately, with the missing frontier
   named in the assertion.
