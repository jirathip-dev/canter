## Root cause (measured, not inferred)

`process::run` waited for the child to exit **before** draining its pipes.
Any output larger than the pipe buffer therefore blocked the child on write:
the parent never read (it was waiting for the exit), the child never exited,
the 30 s deadline fired, the child was killed, and the killed run was
classified from `exit_code() != Some(0)` — reported as
`refusal.intake.issues` whose detail quotes the *captured payload* (a
truncated but plausible-looking issue JSON). The same `gh api` invocation
standalone returns exit 0, which is exactly the asymmetry the issue reports.

The live issue surface is **246 807 bytes** (32 open issues at
`per_page=100`) — three orders of magnitude past a 64 KB pipe.

Reproduced at the base head with the real repository surface and the
pre-fix release binary (dry run; the state store is a copy under `/tmp`, and
its sha256 is unchanged before/after):

```
$ gh api "repos/<owner>/<repo>/issues?state=open&labels=<ready label>&per_page=100"
exit 0; 246807 bytes

$ canter queue intake --repository <owner>/<repo> --label <ready label> \
    --dry-run --integration-branch staging --json
{"error":{"code":"refusal.intake.issues","message":"… could not be read
  (gh api <owner>/<repo> issues): [{\"url\":\"https://api.github.com/…\"…
exit=4
real 0m30.100s      <-- the 30 s deadline, to the tenth of a second
```

The **same command at the delivered head**: `exit=0`, `real 0m3.931s`, 8
selected items rendered in ascending issue order, digest `a052be56…` equal
across two invocations over unchanged facts, and the state store hash
`077e634b…` unchanged.

## The change

- `src/process.rs`: each captured pipe is drained on its own thread while the
  child runs (`drain()`), and the wait loop is unchanged, so the deadline
  still kills a genuinely hung child. `ProcStatus::describe(program, args)`
  and `ProcOut::failure_detail(program, args)` render the cause.
- `src/commands.rs`: the intake refusal now reports
  `«status» ‹program› ‹argv as recorded›; first stderr line: …` instead of the
  captured payload.
- `src/intake.rs`: the rendered decision reports the label **in force**
  (`--label` when presented) instead of the compiled-in default — the
  document must say which label decided.
- `docs/contracts/spec-intake.md`: the label decision (#258 asked for it
  explicitly) plus the diagnosability and drain contracts.
