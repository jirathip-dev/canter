# Lane report — issue #238 (lane `issues-238`)

Lane: worktree `issues-238`, branch `issue-238`, base `origin/staging` =
`1f47577` (the revision this worktree was cut from). Candidate commit:

## 1. The defect

A recorded review FAIL parked the run: the review step consumed the verdict,
`supervision status` reported `class needs-attention (supervision.review_failed),
eligible false`, and nothing continued the run — no fix round, no escalation,
no wake. The fix round existed only as an operator's manual act (hand-created
lane, hand-written brief), which is exactly what the issue's operator record
names.

## 2. The fix (product change)

The review step now hands a recorded FAIL to the run's OWN fix round in the
same effect that consumed the verdict — the same way the reviewer leg is
dispatched today:

- **The leg** is the run's own implementer lane, next round
  (`crate::lane`: `impl-<N>-r<R>` / `issues-<N>-impl<R>`), resolved from the
  run's committed plan: its `harness_start`/`prompt` step supplies the reviewed
  role binding (or the plan-declared key/kind when the run carries no committed
  role configuration) and its `worktree_create` step names the branch. No leg,
  profile, identity or branch is invented or defaulted.
- **The lane** is created (or reused) at the certified head by the engine,
  exactly like the reviewer leg's own lane (#210). A checkout that is not a
  clean linked worktree at the reviewed head refuses `refusal.fix.lane` and is
  left untouched.
- **The instruction** is derived from the recorded verdict: the certified head,
  the observed integration base and the checks the reviewer marked `failed` (a
  passing check is never quoted), plus the run's branch. The engine records
  nothing on the leg's behalf.
- **Delivery** is proven through the same role-bound adapter the rest of the
  spine uses; a spawn the substrate refused is `refusal.fix.spawn`, a prompt it
  did not take is `refusal.fix.prompt`, each carrying the substrate's own code
  in the message.
- **The bound** is `mutation::FIX_ROUNDS_MAX` = the doctrine's own
  `engine::NORMAL_REVIEW_ROUNDS` (3) and is enforced BEFORE any effect: the
  next round on a head the budget cannot cover refuses
  `refusal.fix.bound_exhausted`, whose message names the failures. An exhausted
  budget escalates; it never parks silently.
- **Idempotency**: the engine's own record (`<session>-<step>.fix-round.json`,
  `hf-fix-round/v1`) is keyed by the certified head, so a re-dispatch of the
  same review attempt REUSES the round, and a moved head opens the next one.
- **Classification** (`src/supervision.rs`): `supervision.fix_round_dispatched`
  (class `waiting-workers`, detail = the fix leg's lane),
  `supervision.fix_round_refused` (detail = the fix round's OWN engine code)
  and `supervision.fix_rounds_exhausted`. A FAIL whose review step recorded no
  fix round at all keeps `supervision.review_failed`, now with the review step
  as its detail. `run status` carries the same code: the refusal IS the review
  step's recorded `last_failure` (the #219 read-back).
- **Docs**: `docs/contracts/spec-review-evidence.md` ("The FAIL handoff: the
  run's own fix round") and `docs/contracts/spec-daemon.md` (the classification
  rule).

Files: `src/mutation.rs` (+641), `src/state.rs` (+164), `src/supervision.rs`
(+181/-3), `tests/review_dispatch.rs` (+315), `tests/queue_advance.rs` (+2, the
evidence struct's new field), the two contract docs.

## 5. What this lane did NOT verify / disclosed gaps

1. **Re-review after the fix lands is NOT dispatched by this change.** The fix
   instruction tells the leg to commit and push so the certified head moves, and
   a moved head opens the next fix round — but a fresh REVIEW of the moved head
   is still a separate dispatch. The issue's ACs stop at "reaches a fix round"
   (AC1: "the full cursor from FAIL to the fix lane being prompted").
2. **No live run was executed.** Every witness is the real effect path over
   synthetic fixtures and fake executables, as the repository's public-data
   boundary requires.
3. **The pane substrate is exercised for the FAIL handoff only indirectly**: the
   new witnesses drive the bare-subprocess substrate (the fake harness); the
   pane path shares the same leg/lane/delivery code and the reviewer-leg suites
   cover the pane adapter, but no new pane-substrate fix-round witness was
   added.
4. **The aggregate `just ci` is red on this host** for the two reasons in §4;
   the lane's own diff adds no failure to either set. `just ci` ran at the
   candidate commit's content; `.report-238.md` is a docs-only child commit
   (the repository's report convention).
