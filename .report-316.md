## 1. The defect, re-measured on this host (read-only)

per-scenario daemons of a killed accept-bump harness run plus a review-probe daemon whose binary had

## 2. What the fix does

**`scripts/accept-bump.py` — the bump owns its socket inventory and its residue (AC1, AC2, AC5):**

- The `bump.refusal.socket_holders` refusal (exit 14) now NAMES each holder as
  `pid=<pid> exe=<path|unresolved>` (resolved through the same injected `lsof` boundary), so the
  refusal itself is the reader's inventory of the socket — the heading's claim is checkable, and a
  reader never has to run `pgrep`/`head -1` to guess which process is live.
- New census: `daemon_census()` reads `ps -axww -o pid=,ppid=,command=` (injectable as `--ps`,
  like the other host boundaries) and selects the `canter daemon run` rows reparented to PPID 1. The
  bump records it BEFORE the restart (`orphans_before`) and again after `verify` (`orphans_after`),
  logs both counts and both pid sets, carries both counts in the `bump.done` event, and refuses
  (`bump.refusal.orphans`, exit 18) naming each NEW pid and its command when the count grew across
  the bump. A pre-existing orphan never blocks a bump — a bump that ADDS one never prints DONE.

**`scripts/test-accept-bump.py` — the harness owns the daemons its scenarios start (AC3, AC4):**

- Every scenario daemon is reaped by its own argv (`<root>/state/canter/canter.sock` + the root
  path — the daemon's only durable owner record; the fake supervisor's launcher is gone and `lsof`
  sees only live descriptors). Nothing about the sweep can match a foreign daemon: it is scoped to
  this harness's own disposable workspace.
- Every exit path converges on ONE audit: normal exit, a failed check, a scenario that raised, and
  SIGINT/SIGTERM/SIGHUP (handlers re-enter the same `finally`; a second signal restores the default
  disposition so a stuck reap can never be trapped in). The audit reaps the whole workspace and
  **FAILS the pass** when any scenario daemon is still alive — a leak is a failure, not a residue.
  This is witnessed by a nested failing pass that still leaves nothing behind (§3 W3).
- The kill-proof half: `start_guardian()` starts a separate process that watches the harness pid and
  sweeps the same workspace the moment it is gone (a `kill -9` runs no Python). It treats a
  not-yet-reaped zombie as dead (`ps -o stat=`, not `kill(pid, 0)`), records to
  `<workspace>/guardian.log` instead of its stdout (which may be a pipe that died with the harness),
  and SIGTERMs then SIGKILLs, bounded.

**Docs/runbook (AC5):** `docs/OPERATIONS.md` section 10.1 gains the census step (6), the
`bump.refusal.orphans` row (exit 18), the per-holder naming note, and the census read-back command
(`ps -o pid,ppid,command -ax | grep 'canter daemon'`); `docs/DEVELOPMENT.md` records the harness's
daemon ownership; `CHANGELOG.md` carries the issue #316 entry.

## 5. Changes the fix makes to the existing self-test (disclosed, not hidden)

- `scenario_socket_holders` now also asserts the per-holder naming (AC1) — the refusal's text is
  read, not assumed.
- `Fixture.cleanup()` no longer kills the pids `lsof` sees plus the supervisor's recorded pid (a
  view that misses a daemon whose descriptors are gone, and that is blind on a host without
  `lsof`); it reaps by the daemon's own socket argv. `Fixture.kill()` and `Fixture.supervisor_pid()`
  had no other callers and were removed.
- Every driver invocation in the self-test now passes `--ps <fake>` (the scripted census), so no
  scenario depends on the host's live process table.
- `main()` gained the guardian start, the signal handlers, the single exit audit and the
  host-census read-back; the exit code table is unchanged (0 / 1 / 2), with 130 for an interrupted
  pass that still reaped.

## 6. Disclosed gaps

- **AC2's live bump was not run from this lane.** `accept-bump.py` is operator tooling: a real bump
  installs both paths and restarts the operator's daemon (a host-level change this lane must not
  make). What is proved here: the census/refusal logic (growth → exit 18 naming the new pid; a
  pre-existing orphan → exit 0 with both counts recorded), the real-host census read-back (§3 W4),
  and the runbook commands. The before/after table for a real bump is what the driver now logs on
  the operator's next bump — `orphans_before` / `orphans_after` in the bump log and the
  `bump.done` event.
- **AC4's boundary.** The repo now stops every daemon it starts: scenario daemons are reaped when
  their scenario ends, the exit audit fails a pass that leaves one, and the guardian covers the
  pass that cannot reap itself (SIGKILL) — no repo-started daemon outlives its run beyond the pass.
  A daemon started by an agent *outside* the repo's tooling at an arbitrary path (the measured
  `/tmp/rev272-probe-target` review probe; the two foreign probe daemons alive during this run) has
  no ownership record in canter, so no repo code can attribute it to a run and stop it — exactly the
  limit the issue's own evidence shows. What the repo CAN do about that class is what it now does:
  the census names every PPID-1 `canter daemon` (and refuses a bump that adds one), and the runbook
  carries the reproducible commands a supervision pass can act on.
- The guardian's sweep is bounded (SIGTERM, then SIGKILL, 5 s each) and path-scoped; a daemon that
  ignores SIGKILL, or one whose socket path is outside the harness's disposable workspace, is out of
  its reach by construction. The suite's exit audit would still fail such a pass and name it.
