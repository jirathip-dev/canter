## Part 1 — explicit binding, no literals

  arm `:1215-1226` both call `profile.prompt_binding()?` (`:842`), which
  returns the typed refusal `refusal.binding.missing` (`CODE_BINDING`,
  `:130`) when the profile declares no pair — before any subprocess runs.
  A string-literal sweep of the whole function body (`:1158-1229`) yields
  only flag names (`--provider`, `--model`, `-m`, `-p`, `--print`, `--`,
  `run`, `chat`, `exec`, `-q`, `--continue`, `--create-if-missing`,
  `--json`, `prompt`); no provider/model value literal.
- `grep -rn deepseek src/ tests/` — the only `src/` hit is a doc comment
  (`src/adapters.rs:4700`) quoting the measured jcode missing-key text;
  the `tests/` hits are fake-executable bodies that emulate the real
  binary's measured error text, not argv literals.
- Config surface: `src/config.rs:411-429` decodes `harness.<key>.provider`/
  `model`, validates each token with `is_bare_token` (`:118-124`:
  non-empty, no whitespace, no path separators, no NUL) and requires the
  pair together; violations are named `config.invalid` errors spelling the
  `config.harness.<key>.<field>` path. `Profile::with_binding`
  (`src/adapters.rs:821`) validates at construction
  (`refusal.request.malformed`). An absent binding is not a load error —
  the prompt refuses instead.
- Herdr lifecycle: `refusal.binding.missing` maps to `blocked` with the
  static message `harness provider/model binding required`
  (`src/adapters.rs:1320-1330`; `docs/contracts/spec-capabilities.md:275`).

  returned `provider`/`model`; `:4813` `fn prompt_result_payload` emits
