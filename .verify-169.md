## What the witness drives

The step under the knife is `w1` (`worktree_create`) applied with NO observed
integration base, so `effect_worktree_create` → `lane_integration_base`
(`src/mutation.rs:2609`) → `published_integration_head` (`src/mutation.rs:3831`).
The published read is therefore the FIRST git subprocess of the effect — and,
until it fails, the ONLY one. Every leg is driven through the real daemon
`apply` RPC over a disposable local bare `origin.git` + checkout, with an
executable `git` shim in the sandbox's `fakebin` (first on the daemon's PATH).
The shim appends every invocation's argv to a per-leg log before running its
body, so the witness proves the read — not a neighbouring call — was reached.

- The shim bodies per leg: ordinary exit `exit 128`; mid-read death
  `kill -9 $$`; read deadline `exec /bin/sleep 30` under a declared
  `deadline_secs: 1`; unspawnable read = the shim REMOVED while the daemon's
  PATH is the sandbox's `fakebin` alone (no host git fallback — `execvp`
  skips a non-executable shadowed candidate, so a merely shadowed host git
  would still answer; the narrowed PATH makes the spawn failure REAL).
- The four observations are collected and adjudicated in one aggregate
  assertion, so a mutated guard is reported for every leg it would remap
  instead of hiding the rest behind a first panic.

## Non-vacuity and routing evidence

- The shim's argv log for the deadline leg and for both stock legs contains
  exactly one line, `ls-remote origin refs/heads/staging` — the effect's first
  and only git call is the read the guard sits inside, and the recorded rows
  fail the witness if a neighbouring call ever replaced it.
- Each non-exit leg asserts its own diagnostics survive
  ("died without a terminal outcome" / "exceeded its deadline" / "could not
  spawn") and that the remapped "not readable" text is ABSENT — the RED run
  shows exactly that text appearing for all three once the guard is gone.
- Side effects: in both fixtures the lane was never created
  (`worktrees/issues-123` absent) and neither the checkout's `staging` nor the
  bare `origin.git` `staging` moved.
- The positive control (ordinary exit) proves the read is genuinely reached:
  the mutation does not change its outcome, and its message carries the shim's
  own `exit 128` diagnostics.
