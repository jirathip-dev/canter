## 1. The migration

The #24 dependabot group (`cargo-dependencies`: `sha2` 0.10.9 -> 0.11.0,
`toml` 0.8.23 -> 1.1.6) was red with an API break, not a gate flake, so it is
scheduled here as its own change with its own review.

- `Cargo.toml`: `sha2 = "0.11"`, `toml = "1.1"` — the group's two members,
  verbatim from #24's own diff.
- `Cargo.lock`: regenerated at this head with
  `cargo update -p toml -p sha2` (13 packages re-locked). `generic-array`,
  `toml_edit` 0.22, `toml_write`, and `version_check` leave the tree; the new
  members of the closure are `hybrid-array` 0.4.15, `const-oid` 0.10.2,
  `toml_parser` 1.1.3, `toml_writer` 1.1.2.
- `src/value.rs` `Val::parse_toml`: adapted to the fallible deserializer
  constructor. `toml` 1.x returns the deserializer through a `Result`
  (`Deserializer::parse`; `new` is the deprecated alias), so the 0.8 call
  site's `let de = toml::de::Deserializer::new(text);` no longer hands serde a
  deserializer. The migration propagates the parse error as this module's
  `String` (`map_err(..)?`) through the non-deprecated `parse` name — a
  structural fix, no `allow`/suppression.

## 2. Which member forced which change (the issue asks this explicitly)

- **toml 1.1** forced the `src/value.rs` adaptation above. Its transitive chain
  moves with it (`cargo tree -i toml`: `toml 1.1.6 -> canter`).
- **sha2 0.11** forced `digest` 0.11 and, with it, `block-buffer` 0.12 (via
  `hybrid-array`/`const-oid`). For this tree the `block-buffer` major is
  **transparent** and needs no adaptation: the only sha2 use is
  `Sha256::new()` / `update()` / `finalize()` in `canonical::sha256_hex`,
  which compiles unchanged against `digest` 0.11, and the known-answer test
  pins the digest bytes at the new version.

```
$ cargo tree -i block-buffer
block-buffer v0.12.1
└── digest v0.11.3
    └── sha2 v0.11.0
        └── canter v0.1.0

$ cargo tree -i const-oid
const-oid v0.10.2
└── digest v0.11.3
    └── sha2 v0.11.0
        └── canter v0.1.0
```
