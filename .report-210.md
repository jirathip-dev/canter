## What the live defect was (read-only reproduction)

`run-a1eb1f68dc9f2976` reached `p5-132` with a real certified head and then
refused `p6-132` on every dispatch:

```

  "message":"Herdr name/checkout \"132-rev1\" is held by a different lane; refusing without rename, suffi…
```

(read back read-only from `~/.local/state/canter/state.db`; the run's own
bound plan shows `p6-132` params `worktree: "issues-132"` — the implementer
lane's checkout — while the reviewer leg's derived names are `132-rev1` /
`rev-132-r1`). The engine's refusal was correct (a lane registration must
never be renamed, suffixed or adopted); the PLAN SHAPE was wrong: two legs of
one run bound ONE checkout, and the pane substrate registers one workspace per
checkout — the collision was structural, not incidental.

Design choices, stated plainly:

- **The identity is derived, never respelled.** `(issue, role, round)` →
  agent name, workspace label, lane checkout — one function (`src/lane.rs`)
  used by the spine, the preview, the adapter and the effects. The implementer
  leg round 1 is byte-identical to before (`impl-<N>` / `<N>-impl` /
  `issues-<N>`), so every measured path and the whole #132/#190/#200 lineage
  is unperturbed; only the reviewer leg gains a checkout.
- **Plan-time, not dispatch-time.** The collision class is refused where the
  plan is reviewed (`usage.queue_lane_identity`, naming the reviewer leg AND
  the leg that owns the declared checkout). The effect mirrors the rule
  (`refusal.lane.identity`) as a fail-closed backstop for plans bound by other
  paths, but the preview/submission is the review point the issue asks for.
- **Generation safety is the #190 shape, per leg.** A ledger-terminal run's
  reviewer lane is reclaimed before a successor binds at that identity
  (ownership-verified: the registration must carry exactly that generation's
  lane token; the stale checkout is removed only after its registration was
  closed, and only when git removes it cleanly). A live or foreign holder is
  refused and left untouched — a reclaim never becomes adoption (#157). Every
  retire outcome rides the step outcome, and a failed bind's message carries
  the retire note (#190's rule).
- **The reviewer lane exists FOR the review.** It is created at the certified
  head, verified on retries (moved or dirty → typed refusal, never repaired),
  and removed once the verdict is consumed — a completed review leaves no
  orphan workspace and no orphan checkout. A refused removal is recorded
  verbatim and the residue stays reclaimable by the next generation's bind.
- Nothing widened: no deadline/freshness/retry bound, no suppression/allow
  list, no dependency (`Cargo.toml`/`Cargo.lock` untouched).

## Witnesses

- **W1 — the reviewer leg dispatches without collision while the run's
  implementer lane stays registered.** `tests/review_dispatch.rs::the_reviewer_leg_binds_its_own_lane_while_the_run_lane_stays_registered`:
  the fake substrate holds a multi-workspace state with the run lane (`5-impl`
  at `issues-5`, the run's session) live; the reviewer leg binds its own
  `5-rev1` at `issues-5-rev1`, the recorded `agent start` row carries
  `rev-5-r1`, the lane checkout's HEAD read back at bind time IS the certified
  head, the run lane is never closed or touched, and the consumed review
  removes the reviewer lane (workspace closed + checkout removed, both on the
  outcome). Distinct-by-construction is also pinned unit-level: the rendered
  plan carries both legs' `lane` objects (`rev-5-r1`/`5-rev1`/`issues-5-rev1`
  vs `impl-5`/`5-impl`/`issues-5`).
- **W2 — a plan that would collide is refused at plan time, typed, naming both
  identities.** `tests/queue_preview.rs::a_plan_that_would_bind_two_legs_to_one_lane_checkout_is_refused_at_preview_time`:
  the measured shape (a reviewer leg declaring `worktree: issues-5`) refuses
  `usage.queue_lane_identity` in the message naming `rev-5-r1`, `5-rev1`,
  `issues-5-rev1`, `impl-5`, `5-impl`; a checkout no leg derives refuses too;
  the same step binding its own lane renders. Removing the check makes it RED
  (probe 1).
- **W3 — a retired generation's reviewer lane is reclaimed; a live one is
  never adopted.** `tests/review_dispatch.rs::a_retired_generations_reviewer_lane_is_reclaimed_while_a_live_one_is_never_adopted`:
  with a ledger-terminal run id supplied, the successor's bind closes the
  retired registration (`workspace close R1` strictly BEFORE its own
  `worktree open`), clears the stale checkout (`checkout_removal.removed:
  true`), records both on the outcome, and then binds its own lane at the
  certified head; with a live holder (not in the retired set) the dispatch
  refuses `refusal.lane.name_collision` and nothing at the lane is touched
  (no close row, registration and checkout preserved).
- **AC1 stability** — `a_reviewer_lane_already_at_the_certified_head_is_reused_across_attempts`
  (a retried attempt verifies and reuses its own lane) and
  `a_moved_reviewer_lane_refuses_before_the_reviewer_starts` (a lane at
  another head refuses `refusal.evidence.verdict_stale` deterministically,
  names both heads, and is left untouched — no pane row at all).
- **W4 (non-weakening)** — the full aggregate runs every suite; the
  #190/#191/#173/#157 witnesses (`herdr_pane_execution`'s retire/reclaim
  suite) and #205's certified-head consumption suite are untouched and green
  (`tests/herdr_pane_execution.rs` 28 passed; the full `just ci` matrix).

## Disclosed gaps

1. The repair boundary for UNPROVABLE residue: a reviewer lane whose checkout
   exists but whose registration is gone (or unreadable) is refused and left
   untouched (never deleted unowned) — the same #190 boundary as the
   worktree+branch repair. It is typed (`refusal.lane.identity` /
   `refusal.evidence.verdict_stale`) and named in the message.
2. A lane whose registration exists while its checkout was removed externally
   is reclaimed only up to the point git can act: the bind then refuses with
   git's own error (fail-closed, operator repair).
3. `AGENTS.md`'s canonical-files table could not be updated to name
   `src/lane.rs`: the write to the protected agent-instruction file was
   refused by the host harness (approval prompt timed out) and I did not
   retry it. The module is documented in its own header and in
   `docs/contracts/spec-capabilities.md`.
4. The live run `run-a1eb1f68dc9f2976` is bound to the OLD plan shape
   (`p6-132` binds `issues-132`); after this slice its p6 will refuse
   `refusal.lane.identity` (the plan-time rule mirrored at the effect) and it
   needs a re-rendered plan — an operator action, deliberately not taken here
   (sandbox fenced read-only).
5. The reviewer lane is removed at consume time; a run that dies between the
   lane's creation and its verdict leaves the residue, which is reclaimed by
   the next generation's reviewer bind (W3) — p8 itself does not touch the
   reviewer lane.
