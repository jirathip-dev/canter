## What the contract fixes

- **Canter owns execution and state** (single writer — the shipped daemon);
  the orch owns decisions and acts **only** through the enumerated typed
  operations (`queue; run; grant; lane; supervision`), with pane poking,
  ad-hoc `herdr-spawn` and `gh` merges for canter queues explicitly out of
  contract.
- **The escalation surface** (`canter escalations --json`, read-only): one
  bounded `hf-escalation/v1` page of records carrying `id`/`raised_at`/`run`/
  `issue`/`step`/`state`/`code`/`message`/`bound_heads{certified,published,
  reviewed}`/`needs{orch|human}`/`context`/`answerable_by`, with a null-or-
  ordering-key `cursor`. Four normative rules: listing is read-only; answering
  is a typed operation listed in `answerable_by`; answers are recorded and
  auditable; reading never mutates.
- **The closed code set (v1)**: the 12 shipped park/decision codes
  (`refusal.delivery.moved`, `refusal.delivery.unbound`,
  `refusal.evidence.verdict_stale`/`verdict_pending`/`verdict_missing`,
  `effect.review_timeout`, `refusal.collect.empty_delta`/`collect.unbound`,
  `effect.worker_timeout`, `refusal.run.retry_required`,
  `refusal.lane.name_collision`, `refusal.grant.expired`), additive-only.
  The §4 boundary (routine diagnosed retries are not v1 rows) is disclosed as
  an open item with a witness requirement.
- **The token-accounting note**: per-tick `O(live runs)` document reads
  collapse to one bounded page read; the steady state is an empty page; the
  fleet's measured numbers are marked `[awaiting-evidence]` and assigned to
  the implementing slice.
- **Surface gaps**: `escalation.ack` (proposed `canter escalations ack …`) and
  the answer binding (`--escalation esc_<16hex>` on the answering control) —
  both named as gaps, not built.

## What was deliberately NOT built (the brief's optional clause)

The read-only escalation listing itself. Implementing it properly needs, at
minimum: the emission read + stable `esc_` id derivation; the classification
boundary resolved (which diagnosed parks are escalation rows); the
`escalation.ack` operation and its typed refusals; the answer binding; the
read-only witness (state/audit unchanged across a read) **with its RED
mutation**; a new CLI command with spec-cli/spec-daemon obligations; and a
`tests/*.rs` suite enumerated in the `rust-ubuntu-suite` matrix. That is a
slice with its own review, not a bounded add-on — so §8 of the spec names the
eight remaining items instead of shipping a half-built surface.
