## 1. The defect, stated as the read that never moved

The recorded handoff names the head the FAIL was handed at (`e7bf162…` in the
reported run). That head is a recorded fact and can never move by itself: the
repair leg advances the branch in its OWN lane checkout
(`issues-<N>-impl<R>`, the leg's own worktree, at `220aaeb…` in the reported
run). So every classification that compares "handoff head" against "newest
review evidence head" compares two facts that are the SAME by construction —
`waiting-workers` / `supervision.fix_round_dispatched` forever, on a worker that
has already reported by moving its own head, and a re-dispatched review round
that re-reviews a head whose check can never flip.

The repair leg's own checkout is the only durable state that names the
DELIVERED head. This slice reads it.

## 2. What changed (and what deliberately did not)

1. **The engine's own record names the leg's own lane checkout.**
   `mutation::FixRoundReceipt` (the `hf-fix-round/v1` document, in the
   daemon-owned review root) gains `worktree`: the same derived path
   (`crate::lane::lane_checkout(issue, "implementer", leg.round + round)`) the
   leg was created or verified at, recorded at dispatch. A record written
   before this slice names none.
2. **The daemon reads that checkout's head, read-only.**
   `mutation::observe_fix_leg_checkout(root, worktree, certified)` runs the same
   bounded runner and allowlisted environment every adapter read uses
   (`git rev-parse --verify HEAD`, then `git merge-base --is-ancestor
   <certified> <head>`), contained under the run's recorded `worktrees_root`.
   `supervision::observe_fix_leg` attaches the observation to the evidence
   (`SupervisionEvidence.fix_leg`); the state layer itself still runs nothing.
   The read is taken OUTSIDE the state guard (the status handler and the
   driver's reconcile both release it first).
3. **The disposition is derived from that leg's own state.**
   `supervision::classify`: a recorded handoff whose own checkout holds a
   DESCENDANT head → class `needs-attention`, reason
   `supervision.fix_round_head_moved`, detail = the fix leg's recorded lane
   followed by both 12-character head prefixes (`reviewed at …, delivered at
   …`), `eligible:false`. A leg whose own checkout has NOT advanced keeps
   `waiting-workers` / `supervision.fix_round_dispatched` unchanged; an
   unobserved leg (no recorded lane, unreadable checkout) keeps the recorded
   disposition unchanged — no observation is never a movement.
4. **The next review round binds the DELIVERED head.**
   `daemon::bind_delivered_review_head` (called from `run_dispatch` for a
   review-kind dispatch, outside the state guard): when the recorded handoff's
   leg delivered a descendant head, that head replaces the run's recorded head
   for THIS dispatch, so the reviewer leg's derived checkout materializes the
   delivered commit. The driver's own bounded re-evaluation of the review
   producer (issue #243/#254, unchanged) is what drives it — zero operator
   control.

Deliberately NOT changed: the `hf-fix-round/v1` schema id and its required
fields (the new field is optional and read the same way); the fix-round bound
(`FIX_ROUNDS_MAX`) and the reuse-per-certified-head rule; the re-evaluation
control, its gates and its bound; the review effect's own certified-head
verification and reviewer-lane creation; the run's delivery-certification gate
(issue #202, `refusal.delivery.unbound`); the `fix_round_refused` /
`fix_rounds_exhausted` / `supervision.review_failed` /
`supervision.delivery_unverified` paths; no dependency added; no gate weakened;
`.github/workflows/ci.yml` untouched (no test file was added).

## 5. What this lane did NOT verify (disclosed)

- **A live reviewer leg consuming a verdict at the delivered head.** The
  fixture owns no harness: the re-dispatched review step reaches the effect and
  is refused by the run's own delivery-certification gate
  (`refusal.delivery.unbound`: the head a step consumes must be the head the
  run's own collection certified, issue #202 — untouched). The re-collection
  that certifies a delivered head is NOT part of this slice and no gate was
  weakened to bypass it; the gate's own message names the precondition. What is
  proven is the binding (which head the review round presents, i.e. what the
  reviewer leg's derived checkout materializes).
- **The reported acceptance run (daemon pid 55216, run
  `run-4a4d15a67be20eea`) was not touched**: no live state, no SQLite store, no
  operator control. Its handoff record names no lane checkout (it was written
  before this slice), so the live run keeps its recorded disposition until a
  fresh handoff record is written; the field is only present on records the
  delivered engine writes.
- **A real harness session** (the reviewer's own prompt/delivery) — human-gated
  per `AGENTS.md`; no live reviewer was run.
