## 6. B3 — what was NOT verified

1. **The live drive itself.** The brief forbids touching the live runs, their retry
   rows, the live state store or `~/.config/canter/config.toml`, so the fix is not
   replayed against the real acceptance run. The evidence is the synthetic fixtures
   plus the issue's own recorded texts, which the RED runs of §2 reproduce verbatim
   (`adapter.exit`/`fatal: bad object …`, and the "has no worktree in the integration
   checkout" refusal).
2. **A real Herdr substrate.** `refusal.stale.generation` in the AC6 witness comes
   from the repository's fake `herdr` (file-driven pane/generation tokens), not from a
   real Herdr CLI; real-substrate parity stays the human-gated clean-host smoke
   (issue #7) and this lane does not claim it.
3. **A real forge.** The AC1 witnesses use the fixture `gh` (whose argv is recorded
   and asserted); no network, no real repository, no real account.
4. **The push route was not re-shaped.** The fetch-before-read change is scoped to the
   `pull_request` route, where the landing exists on the remote alone; the `push`
   route's landing is local by construction and its existing tests still pass. No
   push-route fetch test was added because there is nothing to fetch.
5. **Residual risk on other static causes.** `effect.merge.static` parks the frontier
   with the bounded retries UNSPENT for the two causes the issue names (the landed
   commit is unreadable, the lane worktree is missing). Should a third, transient cause
   ever be classified into that code, a re-dispatch would not be spent on it; the code
   always names its cause, the delivery is left exactly where it was, and nothing is
   consumed or rewritten, so the failure mode is a park — never a silent change.
6. **Hosted CI.** This report carries the local aggregate only; the hosted matrix
   remains the authority for the CI hosts, and it re-runs on the PR head.
