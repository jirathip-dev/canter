refuses its own unprovable-base code on **both** routes, so the normative plan
contract (`effect.merge.failed`) is what a consumer actually receives, and both
routes carry a regression witness.

- `src/mutation.rs` (`published_integration_head`): an ordinary non-zero exit
  of the `git ls-remote` read (an `origin` that is absent, unreachable or
  unauthenticated) is mapped to `effect.merge.failed` with the read's own git
  diagnostics kept in the message; the absent-ref route is unchanged. Any
  other subprocess outcome (ambiguous / timed-out) is returned untouched, so a
  deadline can never be reported as "not readable".
- `tests/mutation_engine.rs`:
  `cycle2_rehearsal_refuses_an_unprovable_published_base_on_both_routes` — one
  scenario, two refusals: an absent published ref (the branch P5 showed was
  uncovered) and an unreadable `origin` (RED at the pre-fix tree).
- `docs/contracts/spec-plans.md`: the merge-step contract now states both
  unprovable-base routes and that the refusal carries the read's git
  diagnostics.
- `CHANGELOG.md`: entry naming the finding and the fix.
