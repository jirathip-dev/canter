## Findings addressed

All five surfaces now agree with the implementation:

1. `src/commands.rs`: shipped `canter run --help` says terminal runs can
   release leftover ownership, preserves `done`, and distinguishes same-key
   response replay from a fresh-key audited ownership-absent no-op.
2. `README.md`: the release command row states the same semantics.
3. `docs/contracts/spec-state.md`: the release transaction and live-work
   refusals are accurate; the completing `advance_queue_in_tx` frees only
   its own ownership atomically with `done`.
4. `docs/contracts/spec-daemon.md`: terminal status is not a release refusal;
   in-flight work and unconsumed retry authorizations still refuse typed.
5. `CHANGELOG.md`: the release entry documents terminal recovery and the
   completing advance, rather than the removed terminal-release refusal.

Pause/resume/retry/dispatch still refuse terminal runs. The documentation
names those operations explicitly instead of saying every control refuses.
No source in `src/state.rs`, `src/run_control.rs` or `src/daemon.rs` changes
in this round. Existing ownership, audit, idempotency and restart witnesses
are unchanged; no assertion or gate is removed or relaxed.
