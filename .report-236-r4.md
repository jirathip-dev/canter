## 1. What still diverged at the frozen revision

The issue's item 1 requires that a run's lane records live and die with the
run ("Retiring or releasing a run must retire its lane records for that run,
in the same operation — the reclaim must cover the lane registry rows"). The
landed halves cover the writes: a release frees the run's ownership row in its
own transaction (`State::release_run`), a completing delivery frees it in the
same transaction (the `queue_advance` completion), and the operator control
retires what an invalidation leaves (`run.retire-lane`, #262).

The READ side did not match. `queue intake`'s dedupe read the ownership rows
RAW — any row, whatever its run's recorded state:

```
    let owned: BTreeSet<u64> = state.queue_ownership_rows()
        .into_iter().map(|row| row.issue_number as u64).collect();   // before this round
```

while the shipped contract says exactly:

> An issue that is already **owned or queued** (a **live row** in the recorded
> ownership set for this repository) is **not re-submitted**; it is reported
> with the typed reason `intake.owned`.   — `docs/contracts/spec-intake.md`

So a leftover lane record of a TERMINAL run — the shape the live store still
carries for issue 130 (its run `run-edfe9ebb7f53c4db` has been `done` since
2026-09-14T18:01:23Z; its `queue_ownership` row survives, exactly what
`run retire-lane` retires) — held its issue as `intake.owned` forever, even
though nothing live owned it: the admission would replace the dead row in its
own transaction, and the preview (which reads live runs) already classified
the issue as eligible. `queue intake` was the ONE surface that could be pinned
by a terminal run's lane record.

## 2. The change

- `src/state.rs`: `State::live_owned_issues(repository)` — the issues whose
  `queue_ownership` row names a run recording an owned status (`new`,
  `running`, `paused`, `human_queue`, `blocked` — the SAME set the admission
  conflict re-derives from the run rows and the preview classifies by,
  `queue_preview::OWNED_RUN_STATES`). Read-only; ordered by issue number; it
  never mutates a record.
- `src/commands.rs`: `queue intake` builds its dedupe set from
  `live_owned_issues` (the contract's "live row"). Nothing else changes: the
  `intake.owned` code, the message, the order rule, the bound and the digest
  are untouched.
- `CHANGELOG.md`: the fixed entry.
