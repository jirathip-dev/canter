## 2. What changed

**N7 — a stop is CONFIRMED, never inferred from one status field.** A sample of
the pane worker now reads TWO views of the run's own lane per sample — the lane's
own row (`herdr agent get`, the view the pre-change loop read alone) and its
status row (`herdr agent list`, resolved by internal ownership) — plus the
lane's own `state_change_seq` counter (`adapters::PaneSample`,
`herdr_lane::lane_row`). A sample is a **stop sample** only when the lane's own
row AND the status row report a non-working state (`idle|done|blocked`) and the
lane's counter did NOT move; a stop is **confirmed** only after
`COLLECT_STOP_SAMPLES` (3) consecutive stop samples separated by the REAL
`COLLECT_STOP_INTERVAL_SECS` (5 s) interval (measured off the wait's own clock,
never loop iterations). `refusal.collect.empty_delta` is therefore only ever the
outcome of a confirmed stop; a delivery or emptiness read while the worker is
working stays a wait/re-check (the #147/#200 direction, unchanged). A row shape
that carries no state on the second view corroborates nothing and blocks nothing
(the adapter's own convention for a missing readiness signal), so an older row is
never weaker than the pre-change rule.

**N8 — the wait is bounded by RECORDED PROGRESS, not a wall clock** (the
#232/#233 treatment). The step's effective `deadline_secs` is now the wait's
**no-progress window**; the wait EXTENDS past it while progress is recorded —
the lane reports `working`, its read-back moved (state changed, own counter
advanced), or its collected delivery moved (a new certified head / commit count)
— up to the hard overall ceiling `COLLECT_CEILING_SECS`. A lane that records no
progress for the window parks as the typed `effect.worker_timeout` (ambiguous,
`worker-timeout` / `supervision.worker_timeout`, ineligible) naming the progress
last observed and the elapsed silence; so does a lane still producing progress
at the ceiling. A timed-out read-back is no evidence at all: it breaks the stop
run and the wait re-reads at its cadence. The read-back row's own budget is what
the no-progress window has left, so a row can never outlive the window it is
evidence for.

**N3 (same-code hardening) — a bounded poll rate.** The wait sleeps
`COLLECT_STOP_INTERVAL_SECS` between samples: two subprocess rows per sample, 12
samples/minute, where the pre-change loop polled every ~100 ms (~600/minute for
a worker that runs for tens of minutes).

**N5 — the in-memory collection reservation is keyed by `(run, step)`**
(`daemon::Collections`), so a spine with two collection steps in one run never
has the second silently answered `awaiting <the other step>`; the same step
twice is still the duplicate the slot exists for.

**N4 — the daemon's shutdown invariant is restated EXACTLY.** It is not "no
thread outlives the lease": the supervision driver is cancelled and JOINED
before the lease is dropped, while a bounded collection runs on its own
`canter-collect` thread and is deliberately NOT joined (it can wait on a pane
worker for hours; shutdown neither blocks on it nor cancels the wait that is the
run's own recorded evidence). An interrupted collection is the already-modelled
ambiguous claim, never a second claim. The comment at `src/daemon.rs` (shutdown)
now says exactly that.

**N1/N2/N6 — contract/doc items recorded as accepted limitations** (no code
change; the fail-closed direction of N6 is deliberate):

- N1 (`spec-daemon.md`, "What the continuation window counts"): an in-flight
  collection wait is `waiting-workers` with `eligible:true`, so it also refreshes
  the run's `continuation_reports`; the counter means "the run's own committed
  checks reported it eligible/healthy" and the recorded reason still names which
  one. No safety consequence (`evidence.in_flight` is the second-dispatch gate).
- N2 (`spec-plans.md`): `checkout`/`worktree_create` resolve their base through
  the same published-integration-ref read the merge step uses, so an unreadable
  `origin` refuses with that read's own code `effect.merge.failed`.
- N6 (`spec-daemon.md` + `spec-plans.md`): a `collect_outcome` whose run never
  recorded a succeeded `harness_start` refuses `refusal.incomplete.identity`
  before evaluating any delta.

## 3. The numbers chosen, and why

| constant | value | why |
| --- | --- | --- |
| `COLLECT_STOP_SAMPLES` (N) | **3** | two read-backs is exactly the measured defect (a flap judged a stop); three span two real intervals in which a mid-turn flap has to hold, with the lane's own counter unmoved |
| `COLLECT_STOP_INTERVAL_SECS` | **5 s** | the real interval between stop samples = the poll cadence: 12 read-backs/minute instead of ~600, and well inside the driver's 60 s check interval, so a settled worker is noticed within one tick |
| no-progress window | the step's effective `deadline_secs` — **1800 s** default, plan-declarable `1..=3600` (unchanged numbers) | the policy bound the operator already owns; its MEANING changes from "wall" to "no recorded progress for" |
| `COLLECT_CEILING_SECS` | **21 600 s (6 h)** | ≈4× the measured 93-minute real turn (the work the old 1800 s wall could not wait for) and still a hard bound: a lane that keeps producing progress parks at it |
| read-back row budget | the remaining no-progress window | a read-back cannot outlive the window it is evidence for (the pre-change code bounded it by the remaining deadline) |

Both items are reachable by the live spine: the end-to-end witnesses below drive
`collect_outcome` through the real daemon against the fake Herdr pane source (no
live Herdr, no network, no credentials).
