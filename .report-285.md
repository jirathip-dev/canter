The fix is a read-side change only. A run is TERMINAL BY OUTCOME when its NEWEST recorded
attempt is a step DIAGNOSIS — the same predicate the bounded-retry fence reads
(`step_attempt_diagnosed`) — of a step whose whole bounded-retry budget is spent with no
unconsumed authorization left. Such a run can never be dispatched again: `run retry` refuses
it `refusal.run.retry_bound` and no other exposed control reaches it. One derivation feeds
every consumer that counts lanes: the queue admission's counted-lane set (submit, advance and
the re-drive all read `counted_lane_footprints`), the preview's capacity holds, and the
daemon's dispatch-time fan-out gate. Nothing is released, retried, moved, burned or deleted.

## What I could NOT verify (disclosed)

1. **Scope of the exclusion.** Only the spent-diagnosis park is excluded. A run parked in
   `human_queue` / `blocked` awaiting an approval still counts as a lane: that park is
   advanceable by the recorded human gate and is not terminal-by-outcome. AC1 names the
   retry-exhausted case; the issue's parenthetical is read as the #250 owner-decision
   escalation, which is exactly what this predicate catches.
2. **Boundary note (not exercised).** The predicate keys on the retry bound, not on "no
   re-evaluation applies"; a run whose spent diagnosis also carries an applicable
   `run.reevaluate` control would be excluded from the counted set too. Its operator remedy is
   untouched (nothing is released or blocked), but no fixture of that exact combination is
   committed here.
3. **The live store was not read or touched.** The fence forbids touching the two parked runs,
   so the fix is witnessed on synthetic fixtures only; the durable facts of those two runs were
   not re-queried and this report makes no claim about them.
4. **No CLI-level witness.** The preview read is witnessed through
   `queue_preview::preview_queue` — the same service the `canter queue preview` command calls —
   with a real state store opened from disk; the CLI wrapper itself was not exercised with a
   temporary store for this slice.
5. **Only the per-repository axis is asserted by name** (cap 2, matching the issue's observed
   value). The global and per-harness axes derive from the same counted set and are exercised by
   the existing suite, not by a new assertion here.
6. The pushed head is the candidate plus one docs-only report commit; `just fmt-check` and
   `just security` were re-run at that delivered head (see the closeout below).
