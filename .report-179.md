and the first checkout establish context; no operator retry or redispatch

retains the obstruction: dispatches at t, t+5, t+15, t+35 produce the original
refusal plus exactly three consumed retries. Intervening checks back off.
Later checks have no dispatch, preserve the attempt count, and report
`needs-attention` / `supervision.step_diagnosed`, `eligible=false`, with
`refusal.worktree.exists` as detail.

then attempts the previously derived automatic intent. The operator row is
byte-identical and no new apply attempt appears; only the operator's later
apply consumes it. Existing integration tests also exercise separate CLI
retry/dispatch invocations.

The actual effect witness uses a refused worktree step, not p6/p7. Ambiguous
and failed eligibility are covered by the three-status policy matrix, not
by a fabricated live p6 or merge success. New tests add no wall-clock wait.

budget is durable. This is not a new persistence guarantee for that ladder.
