host home directory, a data volume at 100% full, and — once full — a daemon
whose state store surfaced `state.poisoned: state.write_io: … SQLITE_IOERR
unable to open database file`, indistinguishable from a database fault. Each
required fix has one owner in this diff:

| Required fix | Where |

| 2. disk-pressure admission with a documented floor | `src/lifecycle.rs` (`HOST_FREE_FLOOR_BYTES` = 4294967296 bytes, `refusal.admission.resource_floor`, the gate, and the ONE measurement helper `available_bytes_at`); `src/commands.rs` records the observation in the submit-time proof; `src/daemon.rs` carries it through the dispatch-time renewal and both start parsers |
| 3. the reaper knows the DerivedData classes | `src/mutation.rs` `reclaim_build_residue` — the THIRD half of the lane-residue reclaim (`build_residue`), for ledger-terminal generations only, under the run's own `worktrees_root`, symlinked roots refused |
| 4. typed disk exhaustion (not a raw SQLite error) | `src/state.rs` `classify_write_failure` — below the same documented floor an I/O-class write failure is `state.disk_exhausted`, naming the observation, the floor and the raw detail; a database fault keeps its own code; an unobservable root proves nothing |

## Disclosed gaps and interpretation notes

1. AC1's literal reading ("run a native lane and prove no new directory is
   created in `$HOME`") is witnessed at the fixture level: canter cannot inject
   environment or argv into a Herdr-spawned lane, so its ONE instruction
   channel to the lane is the worker payload the plan produces. W2 executes a
   simulated native build that FOLLOWS that payload — from the lane checkout,
   with the payload's own relative flag — and shows the home directory stays
   empty, with the leaked shape as its discriminating control. A live native
   lane on a real host belongs to the human-gated clean-host smoke class this
   repository never runs from CI.
2. The residue CLASSES the issue measured (`*-derived`, `*-DD`, the
   `DerivedData/*` tree) are derived by NAME from the lane leg, but the roots
   live under the run's own `worktrees_root` — the lane-attributable root the
   issue asks for ("inside its own lane/worktree or a per-lane temp path").
   The reaper deliberately does not sweep arbitrary home-directory paths:
   residue that is not derivable from a lane's own identity cannot be
   attributed to a lane.
3. A host proof that carries NO free-byte observation keeps the pre-#231
   behaviour (freshness decides); making the observation mandatory would refuse
   every existing attestation shape and every current witness fixture. The two
   paths that matter record one — `queue submit --topology` measures the host
   it runs on, and every dispatch-time renewal supersedes it with the daemon's
   own measurement — so every fan-out the supervisor continues is
   floor-checked against a real measurement.
4. The state classification shares the ONE documented floor rather than
   inventing a second number: only I/O-class codes (`SQLITE_IOERR`,
   `SQLITE_FULL`) are reclassified, and only when the observation is below the
   floor. The classification predicate takes the observation as an input, so
   the decision is witnessed without a genuinely full volume.
5. Not verified in this lane: hosted CI (that is the run's own merge gate) and
   any live host lane run. Nothing in this lane pushed to `staging` or `main`,
   bypassed a gate, or executed a live workflow.
