## 1. Preflight: every #134 requirement already holds at this base

The #134 fix landed in `1794ef5` ("Drive armed runs through supervised apply
(Refs #92) (#138)") and is recorded in `cycle2-report.md` as
`#134 stray branch ref | DONE+verified`. Concretely, at this base:

- **The contract decision (required 1)**: the pre-fence screen refuses the
  dangling-symlink shape *before* git runs. `resolve_contained`
  (`src/mutation.rs`) canonicalizes every existing symlink component and
  returns `None` (→ `refusal.path.uncontained`) when the link dangles; the
  clause's comment states the failure mode it closes ("a dangling symlink can
  make `git worktree add` create its branch before failing the filesystem
  operation. Refuse it before git sees the request").
- **Shapes now screen-refused**: `../escaped-lane`, `issues/../../escaped-lane`,
  an absolute destination path, a symlink that leaves the root
  (`link-out/lane`), and the dangling symlink (`dangle/lane`) — all refused
  before `git worktree add` is invoked.
- **The refs regression (required 2)**: `tests/supervision.rs`'s
  `an_uncontained_worktree_dispatch_is_refused_before_any_git_mutation`
  snapshots `git for-each-ref --format=%(refname:short) refs/heads` for the
  integration clone and asserts, per escaping shape, that the inventory is
  unchanged and the branch name is absent — alongside the directory and
  worktree-list assertions.
- **The review addendum (minor)**: the `--lib` case
  `contained_path(&root, ".")` pins the `resolved != root` clause of
  `resolve_contained`.

What remained for this lane is verification the run owes: run the existing
witnesses at the delivered base and run the issue's mutation probe
(required 3) so the new refs coverage is shown to bite. Both follow.
