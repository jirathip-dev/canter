## 1. What the issue asked, at this base

The production half of #101 — ONE clock read per audit record, the SAME instant
building the hash-chained canonical `line` and the persisted `at` column — is
already on `staging` (`457ff4a`, the fix carried by PR #102). What the issue's
own pass/fail list still names as unmet is its first two items: a deterministic
regression test pinning the mechanism at a test-local call-boundary seam (not a
global clock replacement), and a mutation probe proving the test bites. That,
plus the evidence items around it, is the bounded delta here.

## 2. The delta (no production behaviour change)

- `append_audit_at_locked` is the same append with the record's instant supplied
  at the call boundary; `append_audit_locked` binds exactly one
  `time::rfc3339_now()` and hands it down. Every production caller keeps one
  clock read per record and the on-disk bytes are unchanged.
- New unit test
  `state::tests::audit_append_binds_one_instant_to_its_line_and_at_column`
  drives that seam with `2001-02-03T04:05:06Z` (far from any wall-clock read)
  and asserts the stored `at` column is that instant, the `at` inside the
  hashed canonical line is the same instant, the production entry point's row
  satisfies the same column/line invariant, then drops and reopens the state
  and asserts `verify_chain()` is `Ok`.
- No existing test, assertion, or fixture was weakened, moved or deleted; the
  only removed lines are the moved `#[allow(clippy::too_many_arguments)]`, the
  moved one-clock-read comment, and the now-bound `let at = time::rfc3339_now();`
  plus its `&at` borrow.
