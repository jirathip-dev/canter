## What the issue owed, and what the base already had

#132's merged slices already shipped the policy *input* and the rehearsal
shape (`merge_policy` is a closed `squash | ff` input; `effect_merge` is a
read-only rehearsal that never moves the checkout, a ref or the remote), the
published-ref proof (the rehearsal certifies the head read from the
checkout's `origin` remote through `git ls-remote`), the split refusal causes
(policy divergence vs moved base) and the unprovable-base refusal on both
routes (PR #168). The issue's LAST requirement was still unmet:

> Whatever shape is chosen, the run's `merge` step must never leave the
> integration checkout diverged from the published integration ref, and the
> run must be able to complete on a repo whose policy is squash.

The spine's last step is `cleanup`, whose landed proof was ancestry-only
(`git merge-base --is-ancestor <branch> <integration>`). This repository
SQUASH-merges the PR into `staging` (that is how #126/#128/#129 and every
landing of this acceptance arrived): the delivered commits are rewritten, so
the lane head is never an ancestor afterwards and `cleanup` refused
`refusal.cleanup.unmerged` forever. The run could therefore never commit its
own p8 step — it could never complete.

## The gap this round closes

`effect_cleanup` now proves the *landing*, not merely the ancestry:

- **ancestry** — the branch head is an ancestor of the integration ref (an ff
  landing): unchanged, and the deletion still goes through git's own `-d`.
- **content** — every path the branch changed relative to its fork point
  (`git merge-base <branch> <integration>`) is byte-identical in the
  integration ref (`git diff --name-only <branch> <integration> -- <changed
  paths>` is empty): the policy SQUASH landing, which is never an ancestor,
  is proven by the same content fact the merge rehearsal certifies for
  `squash`. The deletion then uses `-D` (git's own merged check cannot pass a
  squash landing; without the proof the new code would surface a bare,
  misleading `adapter.exit` — probe P-B measures exactly that).

The refusal is unchanged and fail-closed: an unlanded branch, a dropped
path, an unlanded deletion or any later divergence still refuses
`refusal.cleanup.unmerged`, now naming how many of the branch's changed paths
are not content-identical (and the first one). The salvage document the
daemon journals before the deletion now names the proof that cleared it
(`landed_by`: `ancestor` | `content`, the content route also carrying the
`merge_base` it compared from), so the audit can tell an ff landing from a
squash landing.

## Scope notes and what is deliberately NOT in this lane

- Only `effect_cleanup`'s landed proof changes. `branch_delete` keeps its
  ancestry-only proof: it is not on the spine (its deletion path is not what
  completes a run) and this slice does not widen it; a plan that deletes a
  squash-landed branch by `branch_delete` still refuses, and that is a
  boundary recorded here, not a claim of this diff.
- The changed paths ride as git pathspecs, so a path whose *name* contains a
  glob metacharacter can only make the check stricter (more paths compared),
  never more permissive; no deletion can pass with differing content.
- The uncovered ambiguous/timed-out non-remap guard in
  `published_integration_head` (tracked as #169) and the bounded-collection
  follow-ups (#170) are untouched — they are not introduced by this diff.
- The merge rehearsal itself (policy input, published-ref certification,
  unprovable-base refusals) is untouched.
- No dependency, `Cargo.lock`, schema, migration or step-param change; no
  `--force` path is added anywhere.
