# Round 1 repair of the cleanup landing proof

Refs #172, #132. Reviewed base: `a33135c6c99108436885a372fc808b687ea8dcc0`.
Implementation candidate: `6a892f13d02b946ad71deb455812ef5951ca43a3`.

## Findings and boundaries

- B-1: changed names now use Git's NUL-delimited output, not C-quoted
  newline records. The text-only subprocess adapter can replace undecodable
  bytes; a replacement character, malformed final delimiter or empty name
  refuses `refusal.cleanup.unmerged`. Literal U+FFFD is conservatively
  refused too. No Unicode normalization or case folding is performed.
- B-2: rename detection is disabled in both diffs. A partial landing is
  any mismatch on a lane-changed path: an addition absent/modified, an
  unlanded deletion, or only one endpoint of a rename landed. Such lanes
  refuse; unrelated integration-only paths do not block a complete landing.
- B-3: literal pathspecs prevent Git from interpreting glob characters or
  pathspec magic. This is explicit protection, not an argument that patterns
  can only make a comparison stricter.
- NB-4: both contract documents and CHANGELOG describe the actual local-ref
  proof, its fail-closed limitations, and its ancestry/content deletion flags.
  The standalone `branch_delete` proof remains ancestry-only. Cleanup does
  not establish that a forge merge occurred or certify the published remote.

## Retraction of the previous report's reasoning

RETRACTED — `.report-132-r3.md`, lines 162–164:

> The changed paths ride as git pathspecs, so a path whose *name* contains a
> glob metacharacter can only make the check stricter (more paths compared),
> never more permissive; no deletion can pass with differing content.

That assurance was false. Quoted names could match nothing, rename detection
could omit a deletion, and exclusion pathspec magic could omit the very file
being proven. The former report is retained byte-unchanged as historical
review evidence; this round explicitly withdraws that claim rather than
silently rewriting the record. Its safety conclusion must not be relied on.
The implementation above supplies the protection the former report lacked.
