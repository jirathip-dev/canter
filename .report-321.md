The mechanism: any non-passing check marks the delivery unverified
(`refusal.evidence.failed`), the consumer is refused, and the driver's ONE
recovery control (the bounded `run.reevaluate`) re-runs the review at the
SAME certified head — which re-reads the same head-wide red. Each round and
each resulting charge spends the run's bounded-retry budget, the resource
that exists to bound genuinely broken runs (AC1/AC2), and the ledger records
no cause, so attempt 2 reads like the run's own failure (AC3).

## 2. What changed

One reading, everywhere: a check now declares the SCOPE it observed.

- **Contract** (`docs/contracts/spec-review-evidence.md`, new section "The
  check scope"): a check may carry `"scope": "diff" | "head"` (closed set;
  `diff` is the default when omitted, so every pre-#321 record keeps its
  meaning byte for byte). `head` declares a census of the whole head the
  delivery sits on — state the delivery's diff did not produce.
- **`src/mutation.rs`**: `CHECK_SCOPE_DIFF`/`CHECK_SCOPE_HEAD`; a total
  scope reader (`check_scope`); the shared rendering appends `(scope head)`
  to a non-passing head-scoped check (a diff-scoped check renders exactly as
  before); `non_passing_checks_outside_diff` (the head-scoped subset) and
  `checks_blocked_outside_diff` (non-passing non-empty AND all head-scoped);
  `review_verdict_facts` refuses a scope outside the closed set; the review
  brief states the rule.
- **`src/supervision.rs`**: new code `supervision.blocked_outside_diff`. The
  driver's re-evaluation derivation (`reevaluation_intent`) is NOT derived
  for the outside-diff-only shape — a recomputation at the same certified
  head re-reads the same red, so no round is driven and no bounded retry is
  charged. The classification parks the run typed: class `needs-attention`,
  `eligible:false`, detail naming the head-scoped checks WITH their scope,
  the certified head, and the rule ("no review round is driven … the run's
  bounded retries are not charged"). `refusal_doc` renders the engine's own
  `refusal.evidence.failed` refusal (reason naming `…=failed (scope head)`),
  and the human read states "blocked outside the diff: …". A MIXED failing
  set (one diff-scoped failure beside head-scoped ones) is untouched: the
  round is derived exactly as before, bounded by `RUN_REEVALUATION_MAX` /
  the shared per-(run, step) budget. New `retry_cause()` (+
  `RETRY_CAUSE_MAX`) derives the charge's cause from the same facts.
- **`src/state.rs`**: m0015 / schema v15, purely additive —
  `run_retries.cause` (the recorded failure each charge exists for; `''` on
  legacy rows). `record_run_retry` / `consume_supervised_retry` take the
  cause; a HELD authorization keeps the cause it was minted with.
- **`src/daemon.rs`**: the supervised dispatch stamps the charge's cause
  (step's newest diagnosis and/or the engine's refusal of the newest review
  evidence); `run.retry` stamps its own. **`src/run_control.rs`**: the
  `hf-run-retry/v1` read-back carries `cause`.
- **Docs/CI**: `docs/contracts/spec-daemon.md` (the classification + the
  ledger cause), `docs/contracts/spec-state.md` (m0015),
  `README.md`/`docs/OPERATIONS.md`/`scripts/test-build-archive.py` (chain
  v15 / m0015), `CHANGELOG.md`, `skills/lane-reviewer/SKILL.md`,
  `scripts/check-contract-fixtures.py` + its self-test (the closed scope
  set, three new tamper probes).

Nothing is loosened: the tail behind an unverified delivery is still never
driven, `evidence_checks_passed()` still requires every check `passed`
(scope included), and a record written before the scope existed reads as
`diff` throughout.

## 6. Disclosed gaps

- The live fleet's installed daemon is untouched: this change is source-only
  (no install, no deploy, no live run re-executed with the new code). The
  measured scenario is demonstrated from synthetic fixtures that mirror the
  run's recorded shapes exactly (AC4: no live fleet needed).
- An operator `run.retry` whose run has no readable supervision evidence
  records the diagnosis word alone (`diagnosed:<status>`); the rich cause
  needs the evidence row, and the authorization is never refused over its
  cause.
- The census check itself (its fabrication by the reviewer) is a
  reviewer-honesty matter: the engine cannot detect a mislabelled scope, but
  every rendering names the declared scope, so a mislabelled check is
  readable in the record.
