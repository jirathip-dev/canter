## 2. The fix shape (bounded)

`src/mutation.rs`:

- `effect_merge` calls `hosted_ci_gate(ctx, &certified_head)` ONCE, after the
  frozen-head (#202) discipline and BEFORE the publish-route branch, so both
  declared routes (`push` and `pull_request`) publish through the same computed
  gate — a route can never bypass the computation.
- `hosted_ci_gate` reads the forge's own workflow runs carrying the EXACT
  certified head (`gh run list --repo <repo> --commit <certified head> --limit
  100 --json databaseId,workflowName,status,conclusion`) — the head the
  recorded verdict names, never the branch tip. `hosted_ci_state` is purely
  computed: a `completed` run concluding `failure`/`cancelled`/`timed_out`/
  `startup_failure`/`action_required` decides RED on its own; otherwise any run
  not yet `completed` is PENDING; only an all-completed, none-red read is
  GREEN.
- RED refuses typed with its own code `effect.merge.ci_red` and names the
  workflow run, its failing JOB and its failing STEP (read back with
  `gh run view <id> --json jobs`), so the refusal is readable from the durable
  record without a second lookup. PENDING polls on the documented cadence
  (`HOSTED_CI_POLL_INTERVAL_SECS`, 5 s) until the step's own effective deadline
  (`effect_deadline_secs`: a declared `deadline_secs`, else the 60 s per-kind
  default), then refuses typed `effect.merge.ci_pending` — a check still
  running is never read as green.
- Nothing is published on either refusal (the gate precedes every publish).
  An unreadable forge read is its own typed refusal, never an absent check. A
  commit the forge reports no workflow runs for has no hosted check to
  conclude on.
- CI status is COMPUTED, not adjudicated: the gate never reads review
  evidence, so a recorded check (including one that explains a failing CI job)
  may explain a state but can never override a computed red.
- Docs: `docs/contracts/spec-plans.md` — one new bullet in the merge/publish
  contract stating all of the above.

Fixtures (the new read needs a deterministic answer, exactly as the existing
forge reads do):

- `tests/mutation_engine.rs`: `FAKE_GH`, `write_fixture_forge` and
  `write_forge_without_pull_request` answer `gh run list` green; new
  `write_hosted_ci_forge` drives red/pending/green for the witness.
- `tests/queue_advance.rs` and `tests/frontier_carry_forward.rs`: the fixture
  daemons (which already own a PATH/bin dir) get a deterministic green `gh`,

- The gate adds a real requirement to `push`-route merges as well: a repository

  is why the two supervisor-driven fixtures above had to answer the read.
- The bounded wait is the step's effective deadline (per-kind default 60 s;
  a plan may declare `deadline_secs`). A delivery whose checks need longer
  refuses `effect.merge.ci_pending` and requires a re-dispatch — never a
  silent green.
