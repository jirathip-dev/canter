## 1. Preflight: what already landed at the base, and what still cannot happen

Issue #272's own delivery is at the base (PR #275, merged `23a985a`): the ONE derived
continuation for a moved fix delivery is `supervision.recollect.fix_delivery`, the review
re-enters through the run's own bounded control, and the #202 AC2 fence (no head is ever
consumed that no collection observed) is intact. Re-verified read-only at the base; the
lane did not re-implement any of it.

**The residual defect is the re-collect's own precondition, and it is still live at the
base.** The collection the re-collect dispatches is the run's own collector step with its
worktree replaced by the repair leg's lane checkout — and the `branch` binding dropped:

    src/daemon.rs  recollect_step_params()   params.remove("branch");
    src/mutation.rs observed_worktree_branch()  a branch-less checkout refuses
                             `refusal.worker.output_location: worker output location …
                              has no branch`

The lane it observes is created by the engine itself as a DETACHED checkout
(`ensure_fix_lane` → `git worktree add --detach <lane> <certified head>`; the run's feature
branch is already checked out in the run's own lane), and nothing establishes a branch in
it: the fix instruction asks the leg to commit and push, never to attach a branch. The live
repair leg did exactly that and could not attach one afterwards — measured in its own
recorded session (`[detached HEAD c0d30ef] …`; then
`fatal: 'issue-261' is already used by worktree at …/issues-261`). So for the production
shape every re-collect is refused, the bounded dispatch budget is spent on refusals, and
the run never re-enters review: exactly the failure the issue describes, still reachable
through the engine's own machinery.

It was hidden by the merged witness: the fixture attached a branch of its own
(`git checkout -q -b <lane>`) before delivering, so the collection's precondition that the
engine never establishes was fabricated by the test that was supposed to prove it.

## 2. The remedy (smallest correct change)

- `src/mutation.rs` — `observed_worktree_branch`: a DETACHED checkout binds the run's
  RECORDED branch when, and only when, it holds EXACTLY that branch's revision (the
  agreement is verified before either is named, so the certificate can only ever state a
  head its own delivery branch holds). A checkout at another revision refuses typed naming
  both heads; a bound branch absent from the checkout's repository refuses typed; both
  refuse BEFORE any worker is polled. The attached case is unchanged, and a branch is still
  never fabricated for a checkout that carries none.
- `src/daemon.rs` — `recollect_step_params` no longer drops the committed `branch`
  binding: the re-collect presents the committed collector step's own inputs, with only
  the observed worktree replaced by the repair leg's own recorded checkout.
- `tests/queue_advance.rs` — the #272 witness keeps the repair lane EXACTLY as the engine
  creates it (still detached after the leg's commit; the production shape) and asserts the
  certificate names the run's own delivery branch and that the re-collect's own claim
  presents that binding over the leg's checkout.
- `tests/supervision_collection.rs` — the collection's binding contract over a detached
  checkout: accepted at the bound branch's own revision (the fake live worker IS polled),
  refused typed at another revision, refused typed with no such branch (no poll either).
- `docs/contracts/spec-daemon.md` — the rule recorded in the collection contract.
