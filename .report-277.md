## 1. The defect, measured read-only before any edit

`~/.local/bin/canter` is what the per-user LaunchAgent runs, and the acceptance
bump script at `~/accept-bump.sh` (an unversioned home-directory script, not in
this repository) installed the freshly built candidate to exactly ONE path.

```

	program = <home>/.local/bin/canter
	pid = 18175
$ lsof -U | grep -F <state>/canter/canter.sock

$ shasum -a 256 <home>/.local/bin/canter <state>/accept/target/release/canter
87a873639355385419f02915820e3fde686a3e89700ada8961a478746b542005  <home>/.local/bin/canter
87a873639355385419f02915820e3fde686a3e89700ada8961a478746b542005  <state>/accept/target/release/canter
```

Note: the two live paths were byte-identical at recon time
(`87a8736…b542005`, both) because the host had been reconciled by hand per the
issue's "Observed" section; the live non-identical case the issue reports is
reproduced as the induced-failure evidence in §3.3. The mechanism the issue
records is a **single-path install**: a
bump that writes only the acceptance target leaves `<home>/.local/bin/canter`
holding the superseded build, so the `KeepAlive SuccessfulExit=>false` unit —
which launches that path — resurrects the OLD build the moment the bump kills
the running daemon; if it wins the socket the host serves the previous build
while the bump still prints `DONE`, silently invalidating every measurement
taken from that daemon. The live lease read (pid `18175`,
`started_at 2026-09-25T13:10:36Z`) and the supervisor's `program` row are the
two facts the driver now has to certify together.

## 2. The bounded change

| File | What |
| --- | --- |
| `scripts/accept-bump.py` (new) | the versioned bump driver: reconcile → build → install BOTH paths (ad-hoc re-signed) → supervisor program check → restart through the supervisor → proof |
| `scripts/test-accept-bump.py` (new) | the driver's self-test (disposable roots, injected `launchctl`; no host activation) |
| `docs/OPERATIONS.md` §10.1 (new) | the runbook + the typed refusal table + the witness commands |
| `docs/DEVELOPMENT.md` | the self-test row (operator tooling: run by hand, never from CI) |
| `CHANGELOG.md` | the `[Unreleased]` entry |

The driver's contract, in its own order:

1. **reconcile** — `git fetch origin <branch>`, fast-forward check, `checkout -B
   <branch> <sha>`, verify HEAD/branch/tree; then `cargo build --release
   --locked` from that exact tree.
2. **install** — the SAME bytes to BOTH `<state>/accept/target/release/canter`
   and `<bin-dir>/canter` (atomically), then `codesign --force --sign -` and
   `codesign -v` on BOTH; the two paths' post-sign sha256 must be equal
   (`bump.refusal.install_divergence` otherwise). The post-sign sha256 is the
   identity of the executed bytes; the pre-sign candidate sha256 is logged
   alongside it.
3. **supervisor** — the job's own `program` row must be the service path (the
   durable half of the fix: the path the supervisor launches is the path the
   bump writes).
4. **restart** — `launchctl kickstart -k gui/<uid>/<label>`; no detached second
   copy is started.
5. **verify** — exactly ONE pid holds the socket; that pid's executable sha256
   IS the installed sha256; the daemon lease names that pid AND records a start
   that postdates the install (so a superseded daemon cannot pass just because
   the file at its executable path was replaced).

`DONE` is printed only under that proof. Every other outcome is a typed
`bump.refusal.<code>` with a non-zero exit status (2 usage, 4 build, 5 non-ff,
6 reconcile, 7 install, 8 sign, 9 install-divergence, 10 supervisor-program,
11 supervisor-not-loaded, 12 restart, 13 daemon-not-up, 14 socket-holders,
15 stale-daemon, 16 pid-exe-unresolved, 17 lease) — there is no path that
reports success on a stale daemon.

## 4. Disclosed gaps

- **The live accept sandbox was not bumped.** Doing so restarts the live
  `com.canter.daemon` (`launchctl kickstart -k`), a host/service-manager change
  reserved for the operator, and it would disturb the live acceptance drive.
  The bump mechanics are exercised end-to-end against a disposable root with the
  supervisor injected, with real `lsof`/`codesign`/`ps` — the supervisor is the
  only simulated boundary, and the fake refuses to lie: it launches exactly the
  program the spec names and the driver can only pass by proving the launched
  binary is the installed one.
- **The host script `~/accept-bump.sh` is not in this repository** (home
  directory tooling, not tracked anywhere). Landing this driver gives the bump
  path a versioned, self-tested home; re-pointing that host wrapper at
  `scripts/accept-bump.py` is a one-line operator action, deliberately not
  performed from this lane.
- **The local aggregate's `security` leg** is red only on the generated rustdoc
  search index (§3.7); with the build directory outside the tree the aggregate
  is green. Hosted CI scans a fresh checkout and is unaffected. The lane
  worktree's own `target/` was reclaimed by host lane hygiene mid-lane
  (gitignored, regenerable), so the second aggregate ran with
  `CARGO_TARGET_DIR=/tmp/impl-277-target` — the same recipes, a lane-local build
  directory.
