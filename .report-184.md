## Contract implemented (ONE of the two: option 1, self-renewal under policy)

A **live** run whose **own** authorization window lapsed mid-spine renews it
before any effect gate reads the window — an audited `grant.rotation`-class
mutation, same run, same issue revision, same state epoch, supersession named,
new expiry recorded — with **no operator and no `run.retry`**.

### Change

- `src/state.rs`
  - `State::renew_lapsed_run_grant(instance_id, presented_grant, at)` — ONE
    transaction: guards re-derived under the transaction (the run is live:
    `new|running`, unpaused, no pause request, no human queue, no terminal
    blocker, live epoch, and a `queue_ownership` row that still names it; its
    own presented grant is `active`, same epoch, bound to the run's
    repository/issue/revision, and actually EXPIRED; the committed spine still
    owes steps), then the successor grant row (same
    repository/issue/revision/workflow/policy/phase/scope/caps/epoch, new
    content-derived `gr_` id, new recorded expiry), the run re-pointed to it,
    and one `grant.rotation` audit row naming the superseded grant, the
    replacement and the recorded expiry. `None` changes nothing for every
    continuation the engine does not own.
  - `renewal_window_secs` — the renewed window is the **sum of the remaining
    committed spine's own documented effect deadlines** (the worker and
    independent-review round trips the run still owes; a step's declared
    `deadline_secs` counts, an out-of-bounds one falls back to its documented
    per-kind default), clamped to the documented window ceiling.
  - `step_attempt_diagnosed(status, code)` — a pre-effect refusal of the run's
    OWN lapsed window (`refusal.grant.expired`) is **not** a step diagnosis:
    the step never ran, so it neither demands nor consumes a bounded retry.
    One predicate, three readers.
  - `claim_run_retry` uses that predicate (the fence itself is unchanged for
    every real diagnosis: failed/refused/ambiguous work still needs and
    consumes one authorization).
- `src/daemon.rs` — `method_apply_from` renews between the claim and the
  effect gates, re-points `parsed.grant_id` at the successor and runs the
  effect under it (one `run.grant.renewed` log line names both grants, the
  derived seconds and the recorded expiry); the supervised automatic-retry
  decision uses the same diagnosis predicate, so a lapse burns no slot.
- `src/supervision.rs` — the driver's dispatch intent treats a recorded lapse
  refusal as the plain continuation it is (a burned-out budget of stale lapse
  refusals can never hold a frontier), while a fresh review `fail` still holds
  it unchanged.
- `src/mutation.rs` / `src/commands.rs` — the documented window ceiling
  (`GRANT_WINDOW_MAX_SECS`, 30 days) now lives once, in the engine's window
  table, and the CLI's `--expires-in` bound reads it.
- `src/daemon_renewal_tests.rs` (new, 8 witnesses) and `tests/executor_authoring.rs`
  (the cycle-2 CLI witness, rewritten to the #184 contract).
- `docs/contracts/spec-daemon.md`, `docs/contracts/spec-plans.md`,
  `docs/OPERATIONS.md` — three sentence-level corrections where the previous
  text claimed an expired window always refuses.

### Superseded expectation (disclosed)

`tests/executor_authoring.rs::cycle2_expired_grant_rotation_continues_the_same_run_explicitly`
previously required an **operator** sequence (fresh issuance → same-run
rotation → `run retry` → `run dispatch`) to continue a run whose window had
lapsed. #184 removes exactly that requirement, so the test was rewritten as
`cycle2_a_lapsed_window_renews_itself_for_the_same_run_without_an_operator_key`:
the lapsed `run dispatch` now **succeeds**, exactly ONE `grant.rotation` record
names both grants and the derived expiry, `run status` carries the
replacement window, the journal carries no `mutate.run.retry`, and a later
issuance for the same binding is refused as `already_owned`. The
**caller** rotation path itself (a later issuance rotating an expired window
on the same run) is still exercised — see the recorded-lapse witness below,
which rotates through the same production submission transaction.
