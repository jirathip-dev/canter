Every one of those was charged by a condition the run did not create, and only

live ledger.

**The bounded change.** The worktree step's branch half
(`reclaim_lane_residue` in `src/mutation.rs`) reclaimed a stale lane branch only
when the published branch on `origin` carried the same tip (a refresh). A
LOCAL-ONLY delivery whose checkout was already gone therefore refused every
successor forever. Such a branch is now reclaimed as a retired generation's
residue, with the guard read from durable state, never from the substrate:

1. the reclaim still runs only for a ledger-TERMINAL generation of THIS issue,
   and now only while the issue has **no other non-terminal generation**
   (`State::live_run_ids`, the complement of `retired_run_ids`, excluding the
   dispatching run) — a run parked at `needs-attention` keeps a non-terminal
   status, still holds its issue's unique ownership and still needs the issue's
   one lane, so nothing of its branch is touched;
2. the branch is deleted only when **no registered worktree of the integration
   clone has it checked out** — read from the clone's own registration
   (`git worktree list --porcelain` pairs each path with the ref it holds, and
   a registration whose directory is gone still counts, like #282's stale
   entry). A held branch keeps `refusal.worktree.branch_exists`, and the
   refusal now names the holder;
3. the removal is attributable: the residue record names the branch, its tip,
   the issue and the reclaiming generation, and it rides the successor's own
   step outcome plus its journaled idempotency claim (the claim row is the
   audited effect), so a stale delivery stays traceable after the fact.

**Scope decision (disclosed).** The issue's scope line is "the worktree step's
branch-adoption decision only", and that is what changed. The operator control
`run.retire-lane` shares the same residue half, and it deliberately keeps its
own, stricter policy — an explicit, human-issued retirement never deletes a
local-only delivery. The difference is one parameter (`LocalOnlyBranch`) read at
exactly one place, each site pinned by its own witness; the docs
(`spec-capabilities.md`, `spec-daemon.md`, `OPERATIONS.md`, `README.md`,
`CHANGELOG.md`) now state both policies instead of claiming they are identical.
