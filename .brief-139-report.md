## Not verified / limits (stated plainly)

- **Live Herdr server end-to-end**: the witnesses are fake-executable contract tests (the repo's
  AC7 doctrine: no credentials, no host harness) plus the recorded-row evidence. The real
  `herdr 0.9.0` CLI rows and the read-back fields this code parses (`name`, `pane_id`, `cwd`,
  `agent_status`, `tokens`) were checked against the installed CLI's own `--help`, `herdr --skill`
  and `herdr api schema --json` output (read-only); the interactive rows remain
  [awaiting-evidence] until the human-gated clean-host smoke, exactly like the pre-existing
  workspace rows. No fake herdr was replaced by a live call in the daemon path.
- **Multi-issue submissions on the pane substrate**: the pane binds ONE lane worktree per run, so
  a plan that binds several lane worktrees refuses typed on the pane substrate (with the explicit
  `headless` fallback named in the message) instead of creating a pane in the wrong lane. That is
  a deliberate fail-closed behavior, not a silent downgrade; it means a multi-issue submission
  must either select `--execution headless` or be split.
- **`just security` / gitleaks**: not part of this report's gate table beyond `just ci`; the lane
  build directory lives OUTSIDE the worktree, and the tracked-tree scanners are re-run at the
  delivered head (below).
- The daemon-level fixture and the adapter fixtures that pin the pre-#139 bare-subprocess rows now
  select the headless substrate explicitly; that is a test-side contract change, not a product
  fallback (the product default remains the Herdr pane).
