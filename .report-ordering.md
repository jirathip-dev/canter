Design, stated plainly (the same honest boundary #205 disclosed): the engine
cannot stop an external `git push` by a pane worker, and cannot make an external
branch immovable. So the fence is enforced at every CONSUMPTION point of the
review window instead:

| window point | enforcement | status |
| --- | --- | --- |
| a commit BEFORE the reviewer starts | the reviewer is never started on a moved checkout (`refusal.evidence.verdict_stale`) | pre-existing (#200) |
| a commit WHILE the review is open | the verdict is never recorded from a moved checkout (`refusal.evidence.verdict_stale`, naming both heads and the re-entry requirement) | **this change (#207)** |
| a commit AFTER the verdict is recorded | the merge consumes the delivery branch only at the head the verdict names (`refusal.delivery.moved`) | pre-existing (#205) |

Together: a worker cannot push into a fenced review window — any commit anywhere
in the window is refused and forces re-entry into review, never a silent
consumption. "The reviewed head" is a statement about the whole window, not a
moment in time.
