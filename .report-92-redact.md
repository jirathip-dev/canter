## 1. Defect and root cause (as measured, not as assumed)

`redact()` (205 lines at the base) scanned every input position, re-scanned the
remaining input from each one (`find_match`), and materialised a `String` of that
whole remaining input at every candidate (`anchored_match` line 58, again line 96).
Per position the work is quadratic in the tail, so the pass is cubic overall
(~n³/6 character copies), and it allocates the tail at every candidate.

Measured on the real reproducer with the pre-fix release binary (`base-canter`,
built from a scratch checkout of `786419f`, sha256
`ebab578db63257c46d3a9ff9e9fdd6c8bfc09b81c4e88f30023d3102c9f73a9a`):

    plan jirathip-dev/canter 90 --config <hf-config/v1>
      -> no completion in 90.02 s, 0 bytes stdout, 0 bytes stderr

(consistent with the recorded 61.3 s / 420 s stalls and 522/530 samples inside
`redact::redact`; log `ac6-measurement-final.json`).

Deterministic pre-fix cost on a small input, measured with the witnesses below: a
2,000-character no-match input cost **2,001,018 allocations / 1,335,407,624 bytes**
(log `base-red-final.log`, literal base tree + the delivered test file).

## 2. What changed

`src/redact.rs`, implementation region only:

- **One left-to-right pass.** `anchored_match` runs once per position; the pre-fix
  `find_match` tail-rescan is gone. Positions the pre-fix code skipped inside a
  match are still skipped (a match jumps the cursor to its end); positions it proved
  non-matching are still tested exactly once.
- **No tail materialisation.** Prefix tests and the PEM `-----END` search work on the
  character slice (`starts_with_str`, `find_str`); nothing allocates per candidate.
- **Per-position lookahead is bounded for the URL rule.** The rule needs the first
  `/` or `@` at or after each `://` candidate; a memoised cursor (`UrlScan`) answers
  those monotone questions so every helper character is examined at most once per
  call. (Probe P3 in §8 records what happens if that cursor is dropped: the pass
  stays linear, because each scan is bounded by the distance to the next `/`; the
  cursor is what makes the per-position bound explicit rather than amortised.)
- **Span arithmetic preserved byte-for-byte**, including the pre-fix implementation's
  UTF-8 **byte** offsets used as character offsets for PEM end-lines and userinfo
  lengths (`byte_len`, `pem_span`). Non-ASCII inputs therefore also produce
  byte-identical output, and no multi-byte sequence is split (all indices are
  character indices or accumulated byte widths).
- Two `#[cfg(test)]` additions: `mod scale_probe` (candidate-visit / scan-step
  counters, compiled out of every non-test build) and `mod scale_tests`; the
  pre-existing `mod tests` bytes are untouched. `src/main.rs`, `Cargo.toml`, the
  contract corpus and every other module are byte-unchanged.

New file `tests/redact_scale.rs`: the allocation witness, the semantic corpus, the
exhaustive equivalence test, the adversarial/issue-scale budgets, and
`reference_redact` — a verbatim transcription of the pre-fix algorithm used as the
oracle.

Fences held: public API unchanged (`pub fn redact(&str) -> String`); every existing
test intact; no detector relaxed; no dependency added; no unrelated refactor.

## 4. AC2/AC3 — semantics preserved

- **54-case corpus**: every token class and floor boundary (`github_pat_`,
  `ghp_/gho_/ghu_/ghs_/ghr_`, `glpat-`, `xoxb-/xoxp-/xoxa-/xoxr-`, `sk-`, `AKIA`),
  boundary rules (space/newline/`.`/`-`/word-adjacent), PEM blocks (trailing newline,
  none, CRLF, two blocks, unterminated → redact to end, marker at a non-boundary,
  `-----BEGIN` with no END redacts to end), URL userinfo (password, user-only,
  exactly three bytes, two bytes, `/` before `@`, bare `://`, `://@`, scheme-like
  prefixes), non-ASCII userinfo and PEM bodies, newline-heavy prose, adjacent tokens.
  Each case asserts (a) byte equality with the pre-fix oracle, (b) idempotency, and
  (c) marker presence exactly where a secret shape occurs, so over-redaction is
  caught as well.
- **Exhaustive short-string equivalence**: all 1,111,111 strings of length ≤ 6 over
  `{g,h,p,_,:,/,@,-,A,K}` equal the pre-fix algorithm. No counterexample.
- **Existing tests**: the pre-existing redaction unit tests are byte-identical and
  pass; `tests/cli_readonly.rs` (16 passed) still proves the plan binds the redacted
  acceptance revision from `gh` and that raw text hashes differ from it.
- **Unicode**: every index is a character index (or an accumulated byte width), so no
  multi-byte sequence is split and no input panics; non-ASCII behaviour is
  byte-identical to the pre-fix pass, including its byte-offset span arithmetic
  (`unicode_pem_body`, `unicode_pem_after`, `url_nonascii_userinfo`,
  `url_nonascii_one_char`, `unicode_heavy`, `unicode_run`).
